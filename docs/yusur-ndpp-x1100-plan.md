## 1. 目标架构（落在 X1100 User Logic）

```text
  沪A/B 10G          深A/B 10G
      \                 /
   Lightning MAC ×N（厂商，~30ns）
      \                 /
   [NOE 或自研] UDP/TCP 剥头 → payload AXIS @322
              |
     ┌────────┴────────┐
     │  A/B 各解一遍    │
     │  dec_sse_*       │  dec_szse_bin
     └────────┬────────┘
              ▼
         arb_nway          # seq+ch，先到推进；缺口打标不堵
              ▼
         sym_map / CAM
              ▼
         book_engine       # v1: 10档 MBP；v2: 逐笔增量
              ▼
         event_bus（归一化）
           ├─→ LightningDMA → 主机（软核/AMA）
           └─→ MAC TX 组播（硬核，若口够）
```

与先前 UL3524 仿真仓的关系：

- **算法可复用**：`arb_nway`、`dec_bin_generic`、`sym_cam`、粘包/碎包口径  
- **必须改接**：AXIS **64b→32b**（或确认板卡实为 64b）、时钟与 `tuser` 跟 FDK 对齐、去掉假 MAC stub，改挂 LightningMAC/NOE  
- **新建**：`book_engine`（原 v1 明确不做簿）  
- **工程建议**：新分支 `fpga-md-card-x1100/`，不要直接在纯仿真仓里混厂商加密 IP

## 2. 功能切片（交付物）

| 编号 | 能力 | 验收 |
|---|---|---|
| F1 | 单路深 Binary 解码 | 合成/录包 → `event_t` 与软件金模逐字段一致 |
| F2 | 单路沪 Binary 或 FAST（合同定一种） | 同上 |
| F3 | 双路择优 | A/B 乱序、重复、缺口：只出一条；缺口计数正确 |
| F4 | 代码过滤 | CAM 热更；未授权代码不进簿/不进 DMA |
| F5 | 订单簿 v1 | 每 symbol **10 档买卖**覆盖更新（快照驱动）；BBO 旁路 |
| F6 | 订单簿 v2 | 逐笔委托/成交增量维护队列或档量（沪深规则分叉） |
| F7 | 出站 | DMA 到主机 **或** 硬核组播（按口数选） |
| F8 | 上电对账 | 开盘前金模 vs FPGA；失败禁止对客 |

延迟口径（对内）：

- MAC→payload：吃厂商数  
- payload→`event_t`：深 Binary 目标同前（百 ns 级拍数，按 32b 重算）  
- 建簿增量：v1 快照覆盖 **O(1)**；v2 逐笔按设计表  
- 端到端到主机：预期落在 **亚 µs～数 µs**（DMA 230ns + 逻辑），**不要对标 STAC-T0 13.9ns**

## 4. 实现方案要点

### 4.1 时钟与总线

| 域 | 用途 |
|---|---|
| 322.26 MHz | MAC/用户热路径（按官博 32b） |
| PCIe/DMA 域 | LightningDMA；跨域只用 event/book FIFO |
| 主机 | HADOS API、金模、配置 |

32b@322 ≈ 10.3125 Gbps 线速一拍一拍对齐；原仿真 64b 模块要改 keep/拍数预算。

### 4.2 解码

- 深 Binary：定长/半定长切穿或单消息 SAF（回补可 SAF）  
- 沪：合同二选一，**不要同口同时跑 FAST+Binary 两套热路径**（可编译开关）  
- 字段偏移：**CSR 表**，禁止 PDF 常量写死在 RTL  

### 4.3 双路择优

- 键：`{ch, seq}`，不是时间戳  
- 先到且推进 → 转发；重复丢；超前 → 转发+`F_GAP`（不堵）  
- TCP 回补：`F_FROM_TCP`，已见 seq 丢  
- **TCP 碎包/粘包/乱序/重传**：优先用 NOE；自研则单独 `tcp_rx_reasm`+`msg_framer`，不进 322 切穿解码器  

### 4.4 订单簿（本项目新增）

**v1（快照 MBP）— 先做这个**

```
symbol_id → 结构 { bid[10], ask[10], seq, ts }
更新：整帧覆盖 10 档（A 股 L2 快照）
读出：BBO 或 Top-N 增量；全快照定时/按需
存储：URAM/BRAM；symbol 数按实测切
```

**v2（逐笔）**

- 深：委托加/减 + 成交改量；是否维护 order-id 哈希看容量  
- 沪：逐笔 + 可选 50 队列；队列吃 RAM，默认 **不做全市场 50 队列**  
- 集合竞价/状态：旁路事件，簿可冻结规则写进规格  

公开对标：华锐等「软硬融合建簿」居多；片上全深不是国内标配。**先卖稳定 10 档 + 逐笔事件流，再加增量簿。**

### 4.5 与驭数栈的分工

| 层 | 谁做 |
|---|---|
| SerDes/MAC/PCS | Lightning MAC（厂商） |
| 可选 UDP/TCP 卸载 | NOE（能用则用） |
| 解码/择优/簿/过滤 | **我方 User Logic** |
| 主机零拷贝 | LightningDMA + HADOS |
| 柜台/OMS | 不动；只供行情 API |

## 5. 风险清单

| ID | 风险 | 等级 | 征兆 | 缓解 |
|---|---|---|---|---|
| R1 | X1100 公开规格不全，口/资源低于「沪深双 A/B + 出站」 | 高 | P0 发现只 2×10G | 改「卡只做解码+簿+DMA，组播用第二张卡/交换机」；或降到单市场 |
| R2 | User Logic 槽 AXIS/时钟与现仿真 64b 不兼容 | 高 | 样例工程位宽不符 | P0 出适配层；重做 keep/拍数；冻结 `event_t` 逻辑布局 |
| R3 | 片上 RAM 撑不住目标 symbol×档 | 高 | 综合 BRAM 爆 | v1 限 512/2k；热门代码 CAM；冷门只 DMA 事件不建簿 |
| R4 | 沪 FAST 模板变更 / 双栈并存 | 中 | 开盘对账失败 | CSR 模板热更；金模同版本；合同锁定一种 |
| R5 | NOE TCP 能力不够回补 | 中 | 缺口无法填 | 主机 TCP 回补 + FPGA 只消费按序流；或买厂商 TCP IP |
| R6 | 逐笔建簿语义与交易所规则边角（撤单、废单、集合竞价） | 高 | 与券商金模漂移 | v2 单独立项；先事件旁路；规则用例表 + 监管日回归 |
| R7 | 厂商壳闭源，时序/延迟不可控 | 中 | 加逻辑后抖动变大 | 只测 User Logic 增量；端到端用板载时间戳；不承诺 MAC 内数字 |
| R8 | 工具链/许可/加密 bitstream 绑定驭数 | 中 | 无法用纯 Vivado 复现 | 合同要仿真模型/HADEP；CI 以官方容器为准 |
| R9 | 把 X1100 当 UL3524 去追 STAC ns | 高（管理） | 错误 KPI | KPI 改为：解码正确率、择优正确、簿一致、开盘抖动、DMA µs |
| R10 | 现仿真仓与板上双头维护 | 中 | 接口分叉 | 单一 `event_t` 契约；板级 diff 隔离在 `ndpp_adapt` |
| R11 | 2026 广域网 2ms 地板导致产品价值质疑 | 中（商务） | 客户只买解码 | 卖点改为确定性解析+簿+分发，不卖「抢 ns」 |
| R12 | 人力：建簿+FAST+TCP 并行 | 中 | 18 周滑点 | 严格 F1→F3→F5→F6；FAST/TCP 可砍到主机 |
