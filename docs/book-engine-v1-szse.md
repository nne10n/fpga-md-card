# 订单簿引擎 v1 — Top-10 片上 + 全量 DDR（深市 / X1100）

日期：2026-09-01（用户思路采纳：片上 Top-10，全量下放 DDR，并行提吞吐）  
市场：单卡深市逐笔增量  
存储约束：BRAM/URAM 只够热路径小结构，**全量不进片上**

---

## 0. 结论（先答「可不可以」）

**可以，作为 v1 主方案。** 条件是 FDK 证明 User Logic 有 **确定的 DDR 口**（AXI-MM 或厂商 DMA 描述符），且能接受：

- 全量簿的单次更新是 **DDR 延迟级**（通常几十～几百 ns×多次访问，叠加成 **亚 µs～数 µs**），不是 BRAM 单拍；  
- Top-10 与全量 **允许短暂不一致**，用明确的提交/纠偏协议；  
- 吞吐靠 **多 bank 并行、命令队列、写合并、旁路 BRAM 缓存活单热点**，不是靠把全量塞回 URAM。

若实测 **没有** User Logic 可达 DDR：退回「热门子集纯片上」或「全量主机」。

---

## 1. 两层语义

| 层 | 介质 | 内容 | 延迟目标 | 谁消费 |
|---|---|---|---|---|
| **L0 热视图** | BRAM | 每 symbol Top-10 bid/ask + BBO | 线速旁路，数拍～数十拍 | 策略/风控硬路径、硬核组播 |
| **L1 全量簿** | DDR | 活单表 + 全价位聚合（或价位哈希） | 高吞吐，µs 级完成/可批 | 主机 DMA 快照、监管、非极热路径 |

全市场 symbol 数：A 股量级用 **symbol 目录在 DDR**；片上只留 **活跃窗口**（见 §3）的 Top-10 槽，或「无限 symbol 的 Top-10 也放 DDR、片上仅 **N_WIRE=64～256** 锁定标的」——推荐后者以免片上 Top-10 再爆。

**推荐折中（资源仍紧时）：**

- 片上 Top-10：**仅订阅/锁定的 N_HOT（64～256）**  
- DDR 全量：真正全市场  
- 未锁定标的：只写 DDR，不维护片上 Top-10  

这样既落实「全量在 DDR」，又保证片上热路径可综合。

## 2. 架构

```text
              event_t (ORDER/TRADE)
                     │
                     ▼
              ┌──────────────┐
              │ cmd_dispatch │  解码动作: ADD/CXL/TRADE
              └───┬──────┬───┘
                  │      │
         并行叉开 │      │
                  ▼      ▼
            ┌────────┐  ┌─────────────────────┐
            │ L0 path│  │ L1 path (DDR)       │
            │ BRAM   │  │ req FIFO → mem sched│
            │ Top-10 │  │ order table + levels│
            └────┬───┘  └──────────┬──────────┘
                 │                 │
                 ▼                 ▼
            book_delta_L0    book_delta_L1 / page DMA
                 │                 │
                 └────────┬────────┘
                          ▼
                     主机 / 组播
```

**关键：L0 与 L1 并行，L0 不等人 DDR。**  
同一事件先（或同时）推入两条队列；L0 用活单的 **旁路缓存** 或「只对已在 Top-10 价位的更新做快速路径」。

## 3. L0（片上 Top-10）设计

### 3.1 何时能「快」

Top-10 增量若每次都查 DDR 活单，会被 DDR 拖死。因此 L0 需要 **片上微型活单旁路**：

| 结构 | 规模 | 用途 |
|---|---|---|
| `hot_cam` | N_HOT | 哪些 symbol 维护 L0 |
| `order_cache` | 1k～4k 槽 | 仅热门 symbol 的活单副本（与 DDR 最终一致） |
| `top10[N_HOT]` | 固定 | 对外热视图 |

更新规则：

1. 事件 symbol ∈ 热门 → 改 `order_cache` + 修 Top-10 → 立刻 `delta_L0`  
2. 同时把 **同一命令** 写入 L1 队列（交给 DDR）  
3. symbol ∉ 热门 → **只进 L1 队列**，无 `delta_L0`

Cancel/Trade 若 `order_id` 不在 cache：L0 **跳过或标 incomplete**，等 L1 完成后代填（见一致性）。

### 3.2 Top-10 算法

每侧 10 元数组：Add 同价累加；新价插入排序；满则挤掉最差档（活单仍在 cache/DDR）。  
Trade/Cancel：减量，档 qty→0 删除，必要时 **不从片上找第 11 档补位**（补位要扫 DDR 全量价位，贵）。  
v1 约定：**挤出/删空后 Top-10 可能暂时不足 10 档，直到 SNAP 纠偏或 L1 回补请求。** 诚实写进规格，避免假完整。

## 4. L1（DDR 全量）设计

### 4.1 DDR 布局（逻辑）

```
SymDir[symbol] -> { order_root, level_root, seq, flags }

OrderTable: hash(order_id) -> { symbol, side, px, qty, next }
LevelTable: hash(symbol,side,px) -> qty
  或 per-symbol 有序跳表/B+ 在 DDR（实现复杂，v1 用哈希档 + 偶发 SNAP 修 Top）
```

v1 **推荐哈希档 + 活单表**，不做 DDR 上完美有序树（工期与抖动都大）。  
主机若要全深有序快照：L1 周期性 walk 或主机自己根据旁路逐笔建。

### 4.2 访存调度（吞吐关键）

```
cmd_fifo (深度 256+)
    → bank_scheduler   # 按 order_id/symbol 哈希拆 4～8 个虚拟 bank
        → axi_mm ×1..2  outstanding
```

手段：

1. **多 outstanding**：DDR AXI 2～8 深度，藏 RTT  
2. **按 key 分 bank**：同 order_id 入同行队列，保序；不同 id 并行  
3. **写合并**：同档连续加减合并成一次 RMW  
4. **读旁路**：刚写未提交的 qty 从 store buffer 前递  
5. **批量提交**：可选 N 条命令一包，降低控制开销（增大延迟）

吞吐目标（设计指标，上板标定）：  
连续竞价突发下，L1 完成率 ≥ 输入事件率；队列接近满时 **丢 L1 并告警** 或 **反压旁路到主机**（不可反压 MAC）。宁丢 L1 全量一致性，也不堵行情口——同时置 `L1_STALL`，主机改吃逐笔旁路重建。

### 4.3 与 NOE/DMA

若厂商已有「包落 DDR」引擎，评估是否复用描述符环；否则 User Logic 挂 AXI-MM。  
**P0 门禁：** 读 FDK「User Logic ↔ DDR」章节；没有就停 L1。

## 5. 一致性模型（必须写进产品说明）

| 规则 | 含义 |
|---|---|
| L0 领先 | `delta_L0` 可先于 L1 完成发出 |
| L1 最终 | 同一 seq 在 L1 完成后为全量权威 |
| 裂缝 | Cancel 未命中 cache 时 L0 可能短暂错；L1 完成后发 `delta_L0_repair` 或等 SNAP |
| 序号 | 所有 delta 带 `seq`；主机按 seq 归并 |
| SNAP | 热门：对账 L0；全市场：可触发 L1 与主机金模对账 / 重载目录 |

**不要承诺**「任意时刻片上 Top-10 ≡ DDR 全量的精确 Top-10」。承诺改为：  
「锁定标的上，连续竞价稳态下 L0 与金模 Top-10 一致率 ≥ X%；L1 队列不溢出时全量最终一致。」

## 6. 并行与其它低延迟技术（对应你的提法）

| 技术 | 用在哪 |
|---|---|
| L0/L1 双路径并行 | 热视图与全量解耦 |
| 多 bank 命令队列 | 提高 DDR RMW 吞吐 |
| 片上 order_cache | 减少 L0 读 DDR |
| 逐笔旁路第二通道 | L1 溢出时主机兜底 |
| A/B 择优在前 | 降重复写 DDR |
| 写合并 / outstanding | 藏 DDR RTT |
| SNAP 低频纠偏 | 修 Top-10 深度不足 |

不推荐：在 DDR 上强行做全市场有序树的「纳秒」宣传。

## 8. 编码阶段

**D0** P0：确认 X1100 DDR 可达与示例工程带宽  
**D1** L0 only（热门 Top-10 + cache）— 可先上板  
**D2** L1 命令队列 + AXI-MM 活单 RMW 仿真（DDR 模型）  
**D3** L0/L1 并行 + repair/SNAP  
**D4** 吞吐压测：开盘录包回放，看 FIFO 高水位  

无 DDR 时 D2 起停，产品降级为仅 L0 热门。

---

## 9. 风险

| ID | 风险 | 缓解 |
|---|---|---|
| D1 | FDK 无 User DDR | P0 一票否决 L1 |
| D2 | DDR RMW 跟不上开盘突发 | bank 并行；溢出切主机旁路 |
| D3 | L0/L1 撕裂被当成 bug | 文档定义 + repair delta |
| D4 | Top-10 不足 10 档 | SNAP/L1 回补；不装假档 |
| D5 | 双写功耗与逻辑面积 | 未热门只写 L1 |

---

## 10. 一句话

**可以做：片上只跑锁定标的的 Top-10（BRAM），全量逐笔状态机扔进 DDR 多 bank 队列并行消化；两条路径并行，L0 不等 L1，用 seq/repair/SNAP 管一致性。先验证 DDR 口，再写 L1。**
